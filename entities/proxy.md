# 代理模式 (Proxy)

为其他对象提供一种代理以控制(隔离，使用接口)对这对象的访问。

## 动机

在面向对象系统中，有些对象由于某种原因(比如对象创建的开销很大，或者某些操作需要安全控制，或者需要进程外的访问等)，直接访问会给使用者、或者系统结构带来很多麻烦。

如何管理/控制这些对象特有的复杂性？增加一层间接层是软件开发中常见的解决方式。

## 要点总结

- 代理并不一定要求保持接口完整的一致性
- 只要能够实现间接控制，有时候损及一些透明性是可以接受的
- 远程代理、虚代理、保护代理、智能引用等多种形式

## 代理类型

| 类型 | 用途 |
|------|------|
| 远程代理 | 跨进程/网络访问 |
| 虚代理 | 延迟加载（按需创建） |
| 保护代理 | 权限控制 |
| 智能引用 | 引用计数、自动释放 |
| 缓存代理 | 缓存请求结果 |

## 相关模式

- [[decorator]] - 结构相似，但意图不同（装饰 vs 控制访问）
- [[adapter]] - 两者都是包装器，但目的不同
- [[facade]] - 门面提供简化接口，代理控制访问
- [[observer]] - 代理可以结合观察者实现事件传递
